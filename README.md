# BizBot

Telegram-бот для малого бізнесу (перукарні, барбершопи тощо), який дозволяє
власникам створити власний AI-асистент для запису клієнтів — без сайту чи
окремого застосунку.

## Що вміє бот

- **Для власників бізнесу**: реєстрація бізнесу (`/setup`), додавання послуг
  і цін, налаштування графіку роботи (`/schedule`), персональне посилання
  для клієнтів (`/mylink`), перегляд і скасування записів.
- **Для клієнтів**: спілкування з ботом звичайною мовою (українською) —
  бот через OpenAI розуміє намір ("хочу стрижку завтра о 17:00", "скасуй
  мій запис", "мої записи") і виконує бронювання, скасування чи перенесення
  запису.

## Технічний стек

- Python, [`python-telegram-bot`](https://github.com/python-telegram-bot/python-telegram-bot) — Telegram Bot API
- OpenAI API — розпізнавання намірів клієнта та відповіді в чаті
- SQLite — зберігання бізнесів, послуг, клієнтів і записів

## Структура даних

Один бот обслуговує кілька незалежних бізнесів (multi-tenant): кожен запис,
клієнт і послуга прив'язані до `business_id`, тож дані різних власників не
перетинаються.

## Схема бази даних і міграції

Схема SQLite версійована через каталог `migrations/`: кожен файл
`NNNN_назва.py` містить функцію `up(cursor)` і застосовується рівно один
раз, у транзакції, у порядку номерів. Застосовані версії фіксуються в
таблиці `schema_migrations`, тож `python database.py` (або будь-який
запуск бота, який викликає `init_database()`) підтягує лише нові
міграції — і на порожній базі, і на продакшн-базі з даними.

Щоб додати зміну схеми: створити `migrations/000N_опис.py` з функцією
`up(cursor)`. Зміна структури вже існуючої таблиці (нове обмеження,
FK, CHECK) на SQLite вимагає пересворення таблиці — приклад повного
циклу (rename → create → copy → drop) є в
`migrations/0002_scale_and_integrity.py`.

Поточна схема розрахована на десятки-сотні бізнесів і тисячі клієнтів:
- `PRAGMA journal_mode=WAL` + `busy_timeout` — паралельні записи не
  блокують одне одного і не падають з "database is locked".
- `PRAGMA foreign_keys=ON` на кожному з'єднанні — FK більше не просто
  задекларовані, а реально перевіряються.
- Індекси на всіх «гарячих» шляхах (послуги й записи по `business_id`,
  бронювання по `service_id`).
- UNIQUE-обмеження там, де раніше на це покладалась лише перевірка в
  коді: один бізнес на власника, один клієнт на `(business_id,
  telegram_id)`, і найважливіше — лише один підтверджений запис на
  `(бізнес, дата, час)`, що усуває подвійне бронювання при одночасних
  зверненнях клієнтів.

## Запуск локально

1. Встановити залежності: `pip install -r requirements.txt`
2. Створити `.env` із змінними `TELEGRAM_BOT_TOKEN` та `OPENAI_API_KEY`
   (опційно `DB_PATH` — шлях до файлу SQLite, за замовчуванням
   `bizbot_v06.db`)
3. Запустити: `python bot.py`
